# DEPLOYMENT requirements - what the Streamlit dashboard needs, nothing more.
# Streamlit Community Cloud installs this file automatically, so it is kept
# deliberately light. The full pipeline stack lives in requirements-pipeline.txt
# and is what the GitHub Actions workflows install.
#
# Why TensorFlow is NOT here, even though two of the three winning models are
# Keras nets: the dashboard does not need it. training_pipeline/predict.py
# tries to load the .keras file, and if TensorFlow is missing or fails to load
# it falls back to model_{H}h_fallback.pkl - the best non-TF model for that
# horizon, saved by the training pipeline for exactly this case. The accuracy
# cost is small (72h: 0.712 -> 0.669) and the deployment gets no heavy CUDA
# wheels, installs in a fraction of the time, and stays well inside Streamlit
# Cloud's ~1 GB memory ceiling.
#
# Why hopsworks is NOT here: the dashboard reads models from the repo and pulls
# live air quality and weather from keyless APIs. It never touches the feature
# store, so it needs no credentials and no SDK.
#
# Verified: no module in the webapp import graph imports tensorflow, hopsworks
# or shap at module level.
#
# PYTHON VERSION: deliberately left open. Streamlit Cloud currently provisions
# Python 3.14, and the interpreter is fixed when the app is CREATED - it cannot
# be changed later, so pinning to an older Python here would strand anyone whose
# app already exists. No version cap is placed on pandas/numpy for the same
# reason: pandas 2.x publishes no cp314 wheels, so `pandas<3.0` fails outright
# on 3.14 while resolving fine on 3.11. Leaving it open lets pip pick 2.x on
# 3.11 and 3.x on 3.14, and the code paths used here are stable across both.

streamlit>=1.32
plotly>=5.18

numpy>=1.26
scikit-learn>=1.3        # StandardScaler inside the saved model bundles

lightgbm>=4.0            # in case a retrain picks LightGBM as the fallback
